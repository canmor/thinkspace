# Generative UI Engine v0.1 — proposed
Target: native ChatGPT-comparable cognitive experience, not pixel copying. Presentation intelligence, layout intelligence, visual expressiveness, interactivity, conversation integration and iterative refinement. Text when sufficient. GenUI is a core product feature.

Harness: role/objective, presentation policy, design guidelines, shared catalog, protocol instructions, interaction and grounding policies, examples. Version all. Model chooses expression and composes primitives; design system owns typography, spacing, color and theme; renderer handles responsive layout; deterministic runtime owns local calculation; host owns permissions. Evaluate failure modes before modifying prompts.

Rich Response Document: ordered Markdown, declarative UI, vector graphics, interactive blocks and future executable blocks with stable IDs. Protocol adapter parses/normalizes/validates, renderer supports inline and independent artifact. Semantic block streaming with started/delta/validated/completed/failed events; preview is not trusted final state; isolate block failure and preserve usable text. Local interaction does not call LLM; explicit AI action passes structured state into a new request. Promote block to canvas and support independent restoration. Future sandbox executable UI only after security validation.

Reuse OpenAI Apps SDK UI design tokens and controls, not presumed access to ChatGPT's proprietary generation system. Compare json-render and OpenUI Lang, A2UI and ChatKit as research alternatives. No custom DSL before evidence. Free SVG subset and reactive expressions essential. Candidate protocols' exact version capabilities, licenses and native renderer parity unverified. React renderer first; portable specs may enable SwiftUI later; Web-specific artifacts can retain Web rendering. See spike.
