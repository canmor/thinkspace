# Experiment B · Revision efficiency

Both arms used the original catalog and host migration. For each protocol and seed they started from the same saved B04 response or the same manually authored fresh-task origin. Both received the complete preceding artifact, current controls and prior user requirements. The reference returned a complete ordered response. The incremental arm returned named declaration or element operations in a strict packet. Its shorter system instructions omit examples of full response envelopes, so input-token differences include prompt overhead. Three successive turns per trajectory give 48 revisions per arm.

All 81 publications preserved the previously selected semantic values observed in the independent audit. Numeric outputs passed across 2,032 full-arm and 2,280 incremental-arm input combinations. The ticket presentation change and water plot removal are tested explicitly. The previously delivered B05 curve was checked across whole weights independently of the selected weight. A turn-three comparison can display both policy fees with the original fee curve retained. Each of 32 first-turn selection actions succeeded, including numeric International controls.

Two json-render water revisions in the incremental arm introduced the rate at 2 litres/minute although the request specified 3. The model can express the rate domain as an element, but the experimental packet cannot supply a separate new-field initial state in the response envelope. The adapter initially uses the lower bound. Both episodes subsequently accepted the requested interaction and computed the right results across the input domain. This is a real semantic degradation despite successful publication, migration of existing fields and correct formulas.

Incremental revision reduced visible output and median latency in these lanes. The completion-token reduction was smaller (11.0%), and the complete-trajectory count was identical. Replacing a whole plot declaration remained expensive; all four json-render water plot revisions truncated. Formatting changes and prose rewriting contribute to full regeneration's changed-declaration counts; these are measures of modification scope. A changed line alone does not establish an unintended regression. The independent domain tests and the new-field default failures supply the behavioral evidence.

The median size of a parseable returned full specification was 612 bytes across 45 calls. A returned patch packet had median size 619 bytes across 43 calls. The packet includes operation metadata, and the accepted task mix differs by arm. Compare paired turn records for a given artifact before interpreting savings. revision-effects.json records complete before/after source sizes and changed identifiers; measurements.json records individual input, completion, visible-estimate, provider timing and repair data. Each failed call and turn remains in revisions/.

Three core modules add 149 lines of reconstruction, transaction and migration logic, plus the Worker command, host lab adapter, test corpus and replay infrastructure. Calls can reconstruct a much larger complete specification from a short patch. The host still pays for complete admission and runtime evaluation. Migration requires domain knowledge and an unambiguous identity mapping. A production decision requires stronger field identity and a way to initialize newly introduced fields before the measured savings can justify making patching the default.
